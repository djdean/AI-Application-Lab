# Creating an AI Search Index via Azure Portal

## Overview

This hands-on lab guides you through creating a vector search index using **Integrated Vectorization** in Azure AI Search. This approach automates the chunking and embedding process directly within the Azure Portal—no code required.

Once created, this index will be used by a **Microsoft Foundry Agent** to perform RAG (Retrieval-Augmented Generation) queries.

---

## Prerequisites

Before starting this lab, ensure you have:

- [ ] **Azure AI Search** service created
- [ ] **Azure OpenAI** service with `text-embedding-ada-002` model deployed
- [ ] **Azure Storage Account** with a Blob container
- [ ] **PDF files uploaded** to the Blob container for testing
  - Upload sample documents (PDFs, Word docs, or text files) that you want to search
  - Ensure files are accessible in the storage container

> 💡 **Tip**: Use the `upload_to_blob.ipynb` notebook in the `backup/search_indexing/` folder to upload files programmatically, or upload directly via Azure Portal.

---

## What is Integrated Vectorization?

Integrated vectorization is an Azure AI Search feature that:
- **Automatically chunks** your documents into smaller pieces
- **Generates embeddings** using Azure OpenAI (text-embedding-ada-002)
- **Creates a searchable index** with vector, keyword, and semantic search capabilities

📖 [Learn more: Integrated Vectorization](https://learn.microsoft.com/en-us/azure/search/vector-search-integrated-vectorization)

## Step-by-Step: Create Index in Azure Portal

### Step 1: Navigate to Import Data

1. Go to your **Azure AI Search** resource in the Azure Portal
2. Click **Import data (new)** from the overview page

### Step 2: Choose Data Source

Select **Azure Blob Storage** as your data source (Built-in indexer).

Other supported data sources include:
- Azure Data Lake Storage Gen2
- Azure Cosmos DB
- Azure SQL Database
- Azure Table Storage
- Microsoft OneLake
- SharePoint, OneDrive (Logic Apps connector)

### Step 3: Select Scenario - RAG

When prompted "**What scenario are you targeting?**", choose:

| Scenario | Description |
|----------|-------------|
| Keyword search | Basic text search with optional AI skills |
| **RAG** ✅ | Ingest text and simple images (via OCR) to enable AI-powered answers |
| Multimodal RAG | For complex images like diagrams and charts |

**Select "RAG"** for this lab.

### Step 4: Configure Azure Blob Storage Connection

Fill in the connection details:

| Field | Description |
|-------|-------------|
| **Subscription** | Select your Azure subscription |
| **Storage account** | Choose the storage account containing your documents |
| **Blob container** | Select the container with your PDF/documents |
| **Blob folder** | (Optional) Specify a subfolder path |
| **Parsing mode** | Default |

**Optional settings:**
- ☐ Enable document layout detection (Preview)
- ☐ Enable deletion tracking
- ☐ Authenticate using managed identity

### Step 5: Vectorize Your Text

Configure the embedding model:
- Select your **Azure OpenAI** resource
- Choose deployment: `text-embedding-ada-002`
- This will generate 1536-dimensional vectors for each chunk

### Step 6: Vectorize and Enrich Images (Optional)

For RAG scenario, you can enable OCR to extract text from images within documents.

### Step 7: Advanced Settings

Configure chunking and semantic settings:
- **Chunk size**: 2000 characters (recommended)
- **Chunk overlap**: 500 characters (for context continuity)
- **Semantic configuration**: Enable for AI-powered ranking

### Step 8: Review and Create

Review your configuration and click **Create** to:
1. Create the data source connection
2. Create the search index with vector fields
3. Create the skillset (chunking + embedding)
4. Create and run the indexer

⏱️ **Note**: Indexing may take several minutes depending on document volume.

## What Gets Created

| Resource | Purpose |
|----------|---------|
| **Data Source** | Connection to your Blob Storage |
| **Index** | Schema with vector, text, and metadata fields |
| **Skillset** | AI pipeline for chunking and embedding |
| **Indexer** | Orchestrates the document processing |
